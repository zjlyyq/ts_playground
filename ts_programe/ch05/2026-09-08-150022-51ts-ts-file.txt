⏺ 文件是空的，但你提到的"标识符 File
  重复"问题很常见。我来解释一下原因和解决方案。

  原因

  File 是 TypeScript 内置的 DOM 类型（lib.dom.d.ts 中定义的 interface 
  File）。当你在代码中声明同名的 class File 或 interface File
  时，就会与内置类型冲突，产生重复标识符错误。

  解决方案

  方案一：移除 DOM 库（推荐，如果你不需要浏览器 API）

  在 tsconfig.json 的 compilerOptions 中，将 lib 设为不包含 dom：

  {
    "compilerOptions": {
      "lib": ["ES2020"]
    }
  }

  这样 TypeScript 就不会加载 lib.dom.d.ts，File 就只属于你自己定义的了。

  方案二：给自己的类型换个名字

  避免与内置类型冲突，使用更具描述性的名称：

  // 不要这样
  class File { ... }

  // 改成这样
  class MyFile { ... }
  // 或
  class FileEntity { ... }

  方案三：在代码中局部遮蔽（不推荐）

  // 重新声明，覆盖全局（仅在模块作用域内生效）
  interface File {
    name: string;
    content: string;
  }

  但这种方式容易造成混淆，不推荐。

  ---

  最常见的场景：你在写一个 Node.js 或非浏览器项目，但 tsconfig.json 里默认带了
  "lib": ["ES2020", "DOM"]。把 "DOM" 去掉即可。需要我帮你查看当前的
  tsconfig.json 配置吗？

  问题分析

  当 lib 未指定时，TypeScript 会根据 target 自动加载默认库。对于 target:

  解决方案

  在 compilerOptions 中显式设置 lib，只包含你需要的 ES 版本，排除 DOM：

❯ 项目包含多个文件夹。每个文件夹都可以配置一个tsconfig吗？                      

  Thought for 2s (ctrl+o to expand)

⏺ 可以的！TypeScript 支持多项目配置，主要有两种方式：

  方式一：嵌套 tsconfig.json（简单继承）

  每个子文件夹放一个 tsconfig.json，通过 extends 继承根配置：

  ts_programe/
  ├── tsconfig.json            # 根配置
  ├── ch05/
  │   └── tsconfig.json        # 继承根配置，覆盖部分选项
  └── ch06/
      └── tsconfig.json

  子目录的 tsconfig.json 只需写差异部分：

  {
    "extends": "../tsconfig.json",
    "compilerOptions": {
      "lib": ["ES2020"]  // 覆盖：不需要 DOM
    }
  }

  方式二：Project References（官方推荐，适合大型项目）

  根目录用 references 指向各子项目：

  // ts_programe/tsconfig.json
  {
    "files": [],
    "references": [
      { "path": "./ch05" },
      { "path": "./ch06" }
    ]
  }

  每个子项目需要设置 "composite": true：

  // ch05/tsconfig.json
  {
    "extends": "../tsconfig.json",
    "compilerOptions": {
      "composite": true,
      "lib": ["ES2020"]
    }
  }

  编译时用 tsc --build（或 tsc -b）。

  ---

  你的情况建议

  你的项目结构是按章节分文件夹（ch05、ch06…），每个章节可能需要不同的 lib
  配置（比如有的需要 DOM，有的不需要）。方式一（嵌套继承） 就够用了，简单直接。

  需要我帮你给 ch05 创建一个子目录的 tsconfig.json 吗？
