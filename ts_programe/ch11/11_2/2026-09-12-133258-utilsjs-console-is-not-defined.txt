❯ @utils.js 为什么提示 'console' is not defined.                                
  ⎿  Read utils.js (9 lines)

  Thought for 19s, read 4 files, listed 2 directories, ran 5 shell commands (ctrl+o to expand)

⏺ 结论：这是 ESLint 报的错，不是 TypeScript

  no-undef 是 ESLint 的规则，TS 编译器不会说"is not defined"（它只会说 Cannot 
  find name 'console'）。我实际跑了一遍确认：

  $ npx eslint ch11/11_2/utils.js
    8:1  error    'console' is not defined      no-undef
    8:1  warning  Unexpected console statement  no-console

  npx tsc --noEmit -p tsconfig.json 只报了 moduleResolution=node10
  的废弃警告，没有 console 的问题 —— 因为 ch11/11_2/tsconfig.json:19 设了 "lib":
  ["dom"]，DOM lib 里就声明了 console。

  为什么 ESLint 认为 console 未定义

  两个原因叠加：

  1. 这个 .js 文件根本没被忽略掉。 eslint.config.mjs:8 写的是 ignores: ['*.js', 
  '*.mjs']。扁平配置里，不含 /
  的模式只匹配配置文件所在的那一层目录，不递归。实测确认：根目录的 index.js
  被忽略了，但 ch11/11_2/utils.js 会被照常 lint。
  2. ESLint 没有配置任何环境全局变量。 配置里没有
  languageOptions.globals，globals 包也没装（require.resolve('globals')
  直接失败）。所以 no-undef 眼里 console 是个未声明的变量。

  为什么 .ts 文件同样写 console.log 却不报

  tseslint.configs.recommended 内部对 .ts/.tsx 关闭了
  no-undef（因为类型检查已经覆盖了这件事）。我建了个 __noundef_check.ts
  验证，只报 no-console 和 prettier 格式问题，没有
  no-undef。所以这个问题只出现在 .js 文件上。

  三种修法

  A. 按原意把忽略模式改对（推荐）——你现在 11_2/tsconfig.json 已经开了 allowJs: 
  true + checkJs: true，JS 由 tsc 负责类型检查，ESLint 不必再管：

  ignores: ['dist/', 'node_modules/', '**/*.js', '**/*.mjs'],

  B. 想让 ESLint 也检查 JS——补全局变量：npm i -D globals，然后

  languageOptions: { globals: { ...globals.node } },  // 或 globals.browser

  C. 只解决这一个文件——在 utils.js 顶部加 /* global console 
  */（临时手段，下次新建 js 文件还会遇到）。

  要我直接改成 A 吗？改动只有一行。

❯ @tsconfig.json 我对这个文件必须修改了一下,分析一下这个修改造成的影响

⏺ 改了 4 处，其中第 1 处会真正弄坏构建

  ┌─────┬─────────────────────────────────────────┬─────────────────────────┐
  │  #  │                  改动                   │          性质           │
  ├─────┼─────────────────────────────────────────┼─────────────────────────┤
  │ 1   │ allowJs: true→false、checkJs:           │ ⚠️ 行为破坏             │
  │     │ true→false                              │                         │
  ├─────┼─────────────────────────────────────────┼─────────────────────────┤
  │ 2   │ module/moduleResolution: CommonJS+Node  │ ✅                      │
  │     │ → nodenext                              │ 修好了报错，但有新约束  │
  ├─────┼─────────────────────────────────────────┼─────────────────────────┤
  │ 3   │ noImplicitAny 后加注释                  │ 无功能影响              │
  ├─────┼─────────────────────────────────────────┼─────────────────────────┤
  │ 4   │ 与未改动的 lib: ["dom"] 叠加            │ 既有隐患                │
  └─────┴─────────────────────────────────────────┴─────────────────────────┘

  ---
  1. allowJs/checkJs 关掉：utils.js 掉出程序了

  allowJs: false 之后，JS 文件完全不属于 TS 程序 —— 不检查、也不产出。但
  main.ts:1 正引用着它：

  import { toPascalCase } from './utils.js'

  症状 A：类型检查静默失效。 实测把 noImplicitAny 打开就立刻炸：

  main.ts(1,30): error TS7016: Could not find a declaration file for module
  './utils.js'.
  '/…/11_2/utils.js' implicitly has an 'any' type.

  因为 noImplicitAny: false（17 行）把 TS7016 吞掉了，所以 tsc 现在 exit=0
  看着一切正常。strict: true 想给你的类型安全，恰好在这个 import 上漏了个洞 ——
  以后 toPascalCase() 传错参数不会有任何提示。

  症状 B：产物跑不起来。

  $ npx tsc -p tsconfig.json && node dist/main.js
  Error: Cannot find module './utils.js'   # MODULE_NOT_FOUND

  dist/ 里只有 main.js，utils.js 没被复制过去。我把 allowJs 加回来对比，dist/
  立刻多出 utils.js，程序正常打印 —— 确认就是这个开关导致的。

  顺带：include: ["**/*.js"]（21 行）现在是死配置。 模式还在匹配，但 allowJs
  关了之后 JS 一律不入程序，不报错也不生效，留着容易误导。

  2. 换成 nodenext：修好了弃用错误

  "moduleResolution": "Node" 是 node10 的别名，TS 6 起直接报错。实测对比：

  11_2       → exit=0   ✅
  ../tsconfig.json (ch11) → error TS5107: moduleResolution=node10 is deprecated
  ❌

  产物格式其实没变。 最近的 package.json（ts_programe/package.json:26）是
  "type": "commonjs"，nodenext 按它推断，dist/main.js 里仍然是 require +
  __esModule。所以运行时行为一致。

  但引入了新约束：
  - 相对导入的扩展名。CJS 模式下 './utils' 和 './utils.js' 都能解析；一旦
  package.json 改成 "type": "module"，整个目录转
  ESM，那时必须写扩展名（'./utils' 报 TS2835）。main.ts 已经写成
  './utils.js'，是向前兼容的写法。
  - import.meta 在 CJS 下不可用（TS1343）；导入纯 ESM 的包会报 TS1479。
  - moduleResolution: "nodenext" 在 nodenext 下可由 module
  推导，两个都写是冗余（无害）。
  - 还有个跨目录的不一致：ch11/tsconfig.json 仍是 moduleResolution: 
  "Node"，同一批文件被两套配置覆盖，IDE 按就近原则取
  11_2/tsconfig.json，命令行编译 ch11 时却会报 TS5107。

  3. 注释本身没问题

  strict: true 会打开 noImplicitAny，显式 noImplicitAny: false 覆盖它（JSON
  里顺序无关，显式项优先），注释说的是对的。只是它正是第 1 条里静默吞掉 TS7016
  的那个开关，两者叠加才让问题无声无息。

  4. 未改动但值得顺手修的：lib: ["dom"]

  显式写 lib 会覆盖 target 的默认库。target: ES2020 默认给 es2020 + dom +
  dom.iterable，现在只给 dom，而 lib.dom.d.ts 只额外引入 es2015 和
  es2018.asynciterable。实测缺失：

  Promise.allSettled  → 需要 es2020     Object.fromEntries / Array.flat → es2019
  String.replaceAll   → 需要 es2021     WeakRef / Array.at              →
  es2021/2022

  建议 "lib": ["ES2020", "DOM", "DOM.Iterable"]。另外既然 module 已经升到
  nodenext（Node 环境），只给 dom 不给 Node 类型也不太贴 —— 这些脚本跑在 Node
  下，"types": ["node"] + 去掉 dom 可能更合适。

  ---
  建议

  最干净的解法：把 utils.js 改名成 utils.ts，main.ts 里的 './utils.js'
  一个字都不用改（nodenext 下这本来就是正确写法，TS 会把 .js 解析回 .ts）。我在
  /tmp 里复现验证过：

  exit=0    dist/{main.js, utils.js, main.js.map, utils.js.map}    → 输出
  Hello-World

  这样 allowJs: false 保住了、类型检查回来了、产物也完整了，再顺手把 include
  里的 "**/*.js" 删掉。

  11_2/eslint.config.mjs:9 沿用了同样的 '*.js'
  模式，同样不递归，所以那个报错还在。）
